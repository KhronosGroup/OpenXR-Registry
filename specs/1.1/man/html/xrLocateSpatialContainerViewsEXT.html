xrLocateSpatialContainerViewsEXT(3) Manual Page

Name

xrLocateSpatialContainerViewsEXT - Locate views for a set of spatial containers

C Specification

The xrLocateSpatialContainerViewsEXT function locates views for a set of spatial containers.

// Provided by XR_EXT_spatial_container_self_rendering
XrResult xrLocateSpatialContainerViewsEXT(
    XrSession                                   session,
    const XrSpatialContainerViewsLocateInfoEXT* locateInfo,
    uint32_t                                    viewStateCount,
    XrSpatialContainerViewStateEXT*             viewStates,
    uint32_t                                    viewCount,
    XrView*                                     views);

Parameters

Parameter Descriptions

  • session is the XrSession.

  • locateInfo is a pointer to an XrSpatialContainerViewsLocateInfoEXT structure.

  • viewStateCount is the count of the viewStates array.

  • viewStates is a pointer to an array of XrSpatialContainerViewStateEXT structures to be populated by the runtime.

  • viewCount is the count of the views array.

  • views is a pointer to an array of XrView structures.

Description

This function replaces xrLocateViews, allowing an app to query views for multiple spatial containers simultaneously.

Views for all spatial containers are returned in the single views array. The views are ordered based on the index of the spatial container in the XrSpatialContainerViewsLocateInfoEXT::viewLocateInfos array, then the view index for that container.

For example, if an app provides three spatial containers in XrSpatialContainerViewsLocateInfoEXT::viewLocateInfos:

  • Index 0: XR_VIEW_CONFIGURATION_TYPE_PRIMARY_MONO (1 view)

  • Index 1: XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO (2 views)

  • Index 2: XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO_WITH_FOVEATED_INSET (4 views)

Then the runtime must fill out the views array with 7 views:

  • views[0] is the view for container 0.

  • views[1] is the left eye view for container 1.

  • views[2] is the right eye view for container 1.

  • views[3] is the left eye view for container 2.

  • views[4] is the right eye view for container 2.

  • views[5] is the left eye inset view for container 2.

  • views[6] is the right eye inset view for container 2.

If viewCount is not equal to the sum of the view counts for each spatial container’s requested view configuration type, the runtime must return XR_ERROR_VALIDATION_FAILURE.

The runtime may decay the view configuration to a type with fewer views for optimization purposes (e.g. a container is very far away and small such that stereo is imperceptible). If the runtime decays the view configuration, the runtime must still return the original number of views for that container, populating the extra views with duplicates of the decayed views. For example, if XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO is decayed to XR_VIEW_CONFIGURATION_TYPE_PRIMARY_MONO, both index 0 and index 1 will contain the single mono view. Consequently, the total number of views returned in the views array is independent of if the runtime decided to decay any view configurations or not.

The runtime should adapt each XrView::fov returned such that the frustum is as small as possible while still containing the entire bounds of the corresponding spatial container. Runtimes may return non-symmetrical FOVs, for example if a spatial container is at an oblique angle to the user’s view, or is partially occluded by another object. Runtimes may freely position the target rendering surface for the spatial container. Due to the nature of multi-app rendering, where spatial containers are detached from the user, the runtime may return XrView values not suitable for pixel rendering, for example if the spatial container is not visible on screen there are no valid values to set XrView::fov to. In such cases, runtimes must set XrSpatialContainerViewStateEXT::shouldSubmitLayers to false.

The runtime returns additional per-spatial container rendering state information in the viewStates array. If viewStateCount is not equal to XrSpatialContainerViewsLocateInfoEXT::viewLocateInfoCount, the runtime must return XR_ERROR_VALIDATION_FAILURE.

After the runtime queues an XrEventDataSpatialContainerClosedEXT event for a spatial container, this function must return XR_FALSE in XrSpatialContainerViewStateEXT::shouldSubmitLayers and 0 in XrSpatialContainerViewStateEXT::viewStateFlags for the corresponding spatial container.

For spatial containers with actively changing locations in the real world, the runtime should take the container’s motion into account when filling out views to minimize reprojection artifacts.

If xrLocateSpatialContainerViewsEXT is called for one or more spatial containers not currently in the active render set, the runtime must return XR_ERROR_SPATIAL_CONTAINER_NOT_RENDERING_EXT.

Valid Usage (Implicit)

  • The XR_EXT_spatial_container_self_rendering extension must be enabled prior to calling xrLocateSpatialContainerViewsEXT

  • session must be a valid XrSession handle

  • locateInfo must be a pointer to a valid XrSpatialContainerViewsLocateInfoEXT structure

  • viewStates must be a pointer to an array of viewStateCount XrSpatialContainerViewStateEXT structures

  • views must be a pointer to an array of viewCount XrView structures

  • The viewStateCount parameter must be greater than 0

  • The viewCount parameter must be greater than 0

Return Codes
On success, this command returns

  • XR_SUCCESS

  • XR_SESSION_LOSS_PENDING

On failure, this command returns

  • XR_ERROR_FUNCTION_UNSUPPORTED

  • XR_ERROR_HANDLE_INVALID

  • XR_ERROR_INSTANCE_LOST

  • XR_ERROR_RUNTIME_FAILURE

  • XR_ERROR_SESSION_LOST

  • XR_ERROR_SPATIAL_CONTAINER_NOT_RENDERING_EXT

  • XR_ERROR_TIME_INVALID

  • XR_ERROR_VALIDATION_FAILURE

  • XR_ERROR_VIEW_CONFIGURATION_TYPE_UNSUPPORTED
