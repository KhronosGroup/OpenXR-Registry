XrSpatialContainerEXT(3) Manual Page

Name

XrSpatialContainerEXT - Represents a spatial container.

C Specification

An XrSpatialContainerEXT is a handle that represents a spatial container.

// Provided by XR_EXT_spatial_container
XR_DEFINE_HANDLE(XrSpatialContainerEXT)

Description

An application starts rendering through a spatial container with the following steps:

  1. Create a spatial container with xrCreateSpatialContainerEXT.

  2. Modify any state on the container for initial presentation, such as its bounds mode.

  3. Request the runtime show the container with xrRequestSpatialContainerVisibleEXT.

  4. Wait for the runtime to be ready to show the container. When the runtime is ready, it queues an XrEventDataSpatialContainerVisibleChangedEXT event with visible set to XR_TRUE.

  5. Begin rendering for the spatial container.

And tearing down a spatial container is as follows:

  1. Request the runtime hide the container with xrRequestSpatialContainerVisibleEXT.

  2. Wait for the runtime to finish hiding the container. When the runtime has fully hidden the container, it queues an XrEventDataSpatialContainerVisibleChangedEXT event with visible set to XR_FALSE.

  3. End rendering for the spatial container.

  4. Destroy the container with xrDestroySpatialContainerEXT.

Note
Note

By design, this extension delegates visibility and focus management to individual spatial containers. Because the session as a whole no longer represents a single visible or focused object, the session does not transition through the standard OpenXR state machine (READY, SYNCHRONIZED, VISIBLE, FOCUSED). Instead, the session remains in XR_SESSION_STATE_IDLE for its active lifetime, and the rules in https://registry.khronos.org/OpenXR/specs/1.1/html/xrspec.html#ext_spatial_container-changes_to_session_state specify how core OpenXR operations map to this mode.
