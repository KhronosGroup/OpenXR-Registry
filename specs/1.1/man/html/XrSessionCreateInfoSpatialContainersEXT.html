XrSessionCreateInfoSpatialContainersEXT(3) Manual Page

Name

XrSessionCreateInfoSpatialContainersEXT - Enable spatial containers for a session

C Specification

Spatial container support is enabled for a session by chaining an XrSessionCreateInfoSpatialContainersEXT when calling xrCreateSession.

// Provided by XR_EXT_spatial_container
typedef struct XrSessionCreateInfoSpatialContainersEXT {
    XrStructureType    type;
    const void*        next;
} XrSessionCreateInfoSpatialContainersEXT;

Members

When spatial container support is enabled, an XrSession behaves differently. This is because when using spatial containers the session no longer presents image content on the display(s), the spatial containers do so instead. Therefore, when this extension is enabled a session is effectively "headless". Unlike other headless extensions, apps can submit image data through the spatial containers.

Description

Enabling spatial container support alters core OpenXR APIs in the following way.

Figure 1. New session state machine

  • The session never enters the states XR_SESSION_STATE_VISIBLE, XR_SESSION_STATE_FOCUSED, or XR_SESSION_STATE_EXITING. Runtimes must never queue events for these states. These states are replaced by per-spatial container events XrEventDataSpatialContainerVisibleChangedEXT, XrEventDataSpatialContainerInteractableChangedEXT, and XrEventDataSpatialContainerClosedEXT, respectively.

  • The session also never enters the states XR_SESSION_STATE_READY, XR_SESSION_STATE_SYNCHRONIZED, XR_SESSION_STATE_STOPPING. Runtimes must never queue events for these states. There are no replacement for these states.

  • Runtimes must treat the session as running when it is in the state XR_SESSION_STATE_IDLE.

  • Runtimes must treat the session as focused when it is in the state XR_SESSION_STATE_IDLE and at least one spatial container exists which is interactable.

  • The xrBeginSession and xrEndSession functions are no longer needed. Runtimes must return XR_ERROR_SPATIAL_CONTAINERS_ENABLED_EXT when these functions are called. Other extensions may provide replacements for these functions.

  • The xrRequestExitSession function is also no longer needed. Runtimes must return XR_ERROR_SPATIAL_CONTAINERS_ENABLED_EXT when this function is called. Apps that want to exit a running session instead can call xrRequestSpatialContainerVisibleEXT to hide their containers, and destroy the session after all containers are no longer visible.

  • Extensions that would queue additional events when the session starts running is called now must queue those events after session creation. Such extensions are called out below.

XR_EXT_user_presence

XrEventDataUserPresenceChangedEXT

XR_META_boundary_visibility

  • The xrLocateViews function is not valid to call for the session. Runtimes must return XR_ERROR_SPATIAL_CONTAINERS_ENABLED_EXT from xrLocateViews. Other extensions may provide ways to locate the views for a particular spatial container.

  • The xrWaitFrame function must always set XrFrameState::shouldRender to false. Other extensions may provide ways to know if a particular spatial container should update its composition layers.

  • The xrEndFrame function is not a valid way to submit composition layers. If an app sets XrFrameEndInfo::layerCount to a non-zero value, runtimes must return XR_ERROR_VALIDATION_FAILURE. Other extensions may provide ways to submit composition layers for a particular spatial container.

  • Entering the state XR_SESSION_STATE_LOSS_PENDING also closes all spatial containers. Runtimes must queue an XrEventDataSpatialContainerClosedEXT event for each active spatial container before queueing a session state change for XR_SESSION_STATE_LOSS_PENDING.

  • The xrCreateSession function no longer needs a graphics API binding structure. Other extensions may require a graphics binding, for example for a spatial container to render using a graphics API.

The above behavior is slightly different from the behavior in XR_MND_headless. Runtimes must not enable the headless session behavior from XR_MND_headless when spatial container support is enabled for that session.

Note
Note

When spatial containers are enabled, a session transitions between only two states: XR_SESSION_STATE_IDLE (running) and XR_SESSION_STATE_LOSS_PENDING (not running). As a result, runtimes no longer return XR_ERROR_SESSION_RUNNING or XR_ERROR_SESSION_NOT_RUNNING. Instead, when a session is not running, runtimes return either XR_ERROR_SESSION_LOST or XR_SESSION_LOSS_PENDING following the rules in OpenXR core. Furthermore, xrBeginSession, the only function that returns XR_ERROR_SESSION_RUNNING, will now always return XR_ERROR_SPATIAL_CONTAINERS_ENABLED_EXT.
Valid Usage (Implicit)

  • The XR_EXT_spatial_container extension must be enabled prior to using XrSessionCreateInfoSpatialContainersEXT

  • type must be XR_TYPE_SESSION_CREATE_INFO_SPATIAL_CONTAINERS_EXT

  • next must be NULL or a valid pointer to the next structure in a structure chain
