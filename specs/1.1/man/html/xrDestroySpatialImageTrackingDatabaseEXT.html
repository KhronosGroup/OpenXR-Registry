xrDestroySpatialImageTrackingDatabaseEXT(3) Manual Page

Name

xrDestroySpatialImageTrackingDatabaseEXT - Destroy a spatial image tracking database handle

C Specification

The xrDestroySpatialImageTrackingDatabaseEXT function is defined as:

// Provided by XR_EXT_spatial_image_tracking
XrResult xrDestroySpatialImageTrackingDatabaseEXT(
    XrSpatialImageTrackingDatabaseEXT           database);

Parameters

Parameter Descriptions

  • database is an XrSpatialImageTrackingDatabaseEXT previously created by xrCreateSpatialImageTrackingDatabaseAsyncEXT.

Description

The application can call the xrDestroySpatialImageTrackingDatabaseEXT function to release the database handle and the underlying resources when finished with spatial image discovery and update tasks.

The application can call the xrDestroySpatialImageTrackingDatabaseEXT function before calling xrDestroySpatialContextEXT. The runtime must no longer report images managed by this destroyed XrSpatialImageTrackingDatabaseEXT. The runtime must continue to report images managed by other databases.

The runtime must ensure that discovery snapshots returned by xrCreateSpatialDiscoverySnapshotCompleteEXT do not contain images pertaining to destroyed or otherwise invalid XrSpatialImageTrackingDatabaseEXT handles, even if the handle was destroyed after the application called xrCreateSpatialDiscoverySnapshotAsyncEXT. Given that the data in a spatial snapshot is immutable, the application should destroy any XrSpatialSnapshotEXT handles that were created before it destroys database, otherwise the application may receive invalid XrSpatialImageTrackingDatabaseEXT handles when using xrQuerySpatialComponentDataEXT.

The application can call the xrDestroySpatialContextEXT function to release the XrSpatialContextEXT handle before destroying any of the XrSpatialImageTrackingDatabaseEXT handles that XrSpatialContextEXT was created with. The runtime must not implicitly destroy these XrSpatialImageTrackingDatabaseEXT handles when the XrSpatialContextEXT is destroyed.

Managing the lifetime of XrSpatialContextEXT and XrSpatialImageTrackingDatabaseEXT independently enables applications to reuse previously created XrSpatialImageTrackingDatabaseEXT handles without needing to re-perform the costly creation procedure.

For example, destroying an XrSpatialContextEXT and subsequently recreating another XrSpatialContextEXT with the same XrSpatialImageTrackingDatabaseEXT enables pausing and resuming image tracking without needing to perform another initialization procedure.

Valid Usage (Implicit)

  • The XR_EXT_spatial_image_tracking extension must be enabled prior to calling xrDestroySpatialImageTrackingDatabaseEXT

  • database must be a valid XrSpatialImageTrackingDatabaseEXT handle

Thread Safety

  • Access to database, and any child handles, must be externally synchronized

Return Codes
On success, this command returns

  • XR_SUCCESS

On failure, this command returns

  • XR_ERROR_FUNCTION_UNSUPPORTED

  • XR_ERROR_HANDLE_INVALID

  • XR_ERROR_RUNTIME_FAILURE
