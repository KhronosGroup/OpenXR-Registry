XrSpatialArchetypeIdEXT(3) Manual Page

Name

XrSpatialArchetypeIdEXT - ID referring to a spatial archetype

C Specification

// Provided by XR_EXT_spatial_entity_archetypes
XR_DEFINE_ATOM(XrSpatialArchetypeIdEXT)

Description

XrSpatialArchetypeIdEXT is used to represent a spatial archetype which is a unique combination of components that exist on an entity. For the same unique combination of components, the runtime must use the same XrSpatialArchetypeIdEXT in all the spatial snapshots created under an XrSpatialContextEXT. The runtime must not reuse the same XrSpatialArchetypeIdEXT across multiple XrSpatialContextEXT for different combinations of component types. The runtime may reuse the same XrSpatialArchetypeIdEXT across multiple XrSpatialContextEXT if it represents the same unique combination of component types.

Consider the following entities -

  • Entity 1 has components A, B

  • Entity 2 has components A, B, C

  • Entity 3 has components D, E

  • Entity 4 has components A, B

In the above example, the runtime enumerates three archetype ids, one for each unique combination of components - (A, B), (A, B, C), (D, E).

Archetypes are different from spatial capabilities and their list of guaranteed components because the unique combination of component types that make up an archetype may include component types that are optional components for a given capability, and may even span more than one capability.

Consider this real world example of a physical table, where that entity may have XR_SPATIAL_COMPONENT_TYPE_BOUNDED_2D_EXT and XR_SPATIAL_COMPONENT_TYPE_PLANE_ALIGNMENT_EXT because of the XR_SPATIAL_CAPABILITY_PLANE_TRACKING_EXT and XR_SPATIAL_COMPONENT_TYPE_BOUNDED_3D_EXT because of a hypothetical object tracking capability. A wall, on the other hand, may only have XR_SPATIAL_COMPONENT_TYPE_BOUNDED_2D_EXT and XR_SPATIAL_COMPONENT_TYPE_PLANE_ALIGNMENT_EXT. So while both the table and wall are seemingly being discovered by XR_SPATIAL_CAPABILITY_PLANE_TRACKING_EXT, their set of components are different and will therefore be represented by different XrSpatialArchetypeIdEXT.
