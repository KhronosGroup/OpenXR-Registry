XrSpatialContainerViewStateEXT(3) Manual Page

Name

XrSpatialContainerViewStateEXT - View suitability information for a spatial container

C Specification

The XrSpatialContainerViewStateEXT structure is populated by calls to xrLocateSpatialContainerViewsEXT with per-spatial container rendering suitability information.

// Provided by XR_EXT_spatial_container_self_rendering
typedef struct XrSpatialContainerViewStateEXT {
    XrStructureType            type;
    void*                      next;
    XrViewStateFlags           viewStateFlags;
    XrViewConfigurationType    viewConfigurationType;
    XrBool32                   shouldSubmitLayers;
    XrExtent2Di                recommendedImageExtent;
} XrSpatialContainerViewStateEXT;

Members

Member Description

  • type is the XrStructureType of this structure.

  • next is NULL or a pointer to the next structure in a structure chain.

  • viewStateFlags is a bitmask of XrViewStateFlags. These flags have the same purpose as the viewStateFlags in the core XrViewState structure.

  • viewConfigurationType is an XrViewConfigurationType which indicates the view configuration type the runtime is using for the spatial container, which runtimes may decay to a view configuration with a lower number of views than the one requested.

  • shouldSubmitLayers is an XrBool32 returned by the runtime. If XR_FALSE, the app should avoid submitting composition for this spatial container as it is currently not visible or is in a state where rendering is not required.

  • recommendedImageExtent is an XrExtent2Di structure representing the recommended resolution for the spatial container.

Description

As with core OpenXR view location, the app must check the XrSpatialContainerViewStateEXT::viewStateFlags to ensure the position and orientation are valid and tracked before using the view data for rendering.

The app should check shouldSubmitLayers and viewConfigurationType to avoid rendering more than the runtime recommends. When shouldSubmitLayers is false, the app changes its rendering behavior as follows:

  • The app must not read the corresponding XrView::fov.

  • The app must not read recommendedImageExtent.

  • The app should avoid rendering to swapchains and submitting composition layers for the corresponding spatial container.

  • The app should set XrSpatialContainerLayerEXT::retainPreviousSubmission to true. If the app chooses to submit layers anyway, it is up to the runtime to determine what it wants to do with the layers (e.g. the runtime may choose to drop them).

recommendedImageExtent is explicitly for layers that will be updated based on the container position or user’s view. When updating layers with content that depends on the spatial container’s position or user’s view (such as normal 3D content), the app should render to this smaller viewport instead of the default recommended view size. When updating layers with content that does not depend on the spatial container’s position or user’s view (such as static quad layers), the app may safely ignore these values. For view dependent layers, recommendedImageExtent is a recommendation to the app from the runtime intended to minimize aliasing and improve rendering performance. The app is free to submit at full resolution if it wishes.

The XrExtent2Di::width and XrExtent2Di::height of recommendedImageExtent must always be a positive integer less than or equal to the XrViewConfigurationView::recommendedImageRectWidth and XrViewConfigurationView::recommendedImageRectHeight of the XrViewConfigurationView for the spatial container’s primary view configuration. An app should not recreate a swapchain solely because recommendedImageExtent changed, as it is a dynamic hint to the app specifying the XrSwapchainSubImage::imageRect to use in the XrSwapchainSubImage of any full resolution composition layers it submits, and can change every frame.

Valid Usage (Implicit)

  • The XR_EXT_spatial_container_self_rendering extension must be enabled prior to using XrSpatialContainerViewStateEXT

  • type must be XR_TYPE_SPATIAL_CONTAINER_VIEW_STATE_EXT

  • next must be NULL or a valid pointer to the next structure in a structure chain

  • viewStateFlags must be a valid combination of XrViewStateFlagBits values

  • viewStateFlags must not be 0

  • viewConfigurationType must be a valid XrViewConfigurationType value
