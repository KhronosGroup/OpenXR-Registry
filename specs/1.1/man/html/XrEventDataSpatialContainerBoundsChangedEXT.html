XrEventDataSpatialContainerBoundsChangedEXT(3) Manual Page

Name

XrEventDataSpatialContainerBoundsChangedEXT - Event reporting the bounds or bounds mode of a spatial container has changed

C Specification

Every time a runtime changes the bounds or bounds mode of a spatial container, the runtime must queue an XrEventDataSpatialContainerBoundsChangedEXT event with the new bounds information.

// Provided by XR_EXT_spatial_container
typedef struct XrEventDataSpatialContainerBoundsChangedEXT {
    XrStructureType                    type;
    const void*                        next;
    XrSpatialContainerEXT              spatialContainer;
    XrExtent3Df                        bounds;
    XrBool32                           infiniteBounds;
    XrSpatialContainerBoundsModeEXT    boundsMode;
} XrEventDataSpatialContainerBoundsChangedEXT;

Members

Member Description

  • type is the XrStructureType of this structure.

  • next is NULL or a pointer to the next structure in a structure chain. No such structures are defined in core OpenXR or this extension.

  • spatialContainer is the XrSpatialContainerEXT that this event is for.

  • bounds is the new width, height, and depth of the spatial container’s bounds.

  • infiniteBounds is true if the container has infinite bounds.

  • boundsMode is the new XrSpatialContainerBoundsModeEXT of the spatial container.

Description

The event is queued for all changes, including app requested changes and runtime initiated changes.

While a user is interactively resizing a spatial container, runtimes must behave in one of the following ways:

  • queue many events, likely at framerate, as the user is resizing the spatial container

  • queue a single event at the end of the resize

If a runtime queues only a single event at the end of the resize, that runtime must continue to report the old bounds from xrGetSpatialContainerBoundsEXT until the runtime queues a resize event. Runtimes must coalesce multiple unpolled bounds changed events. In other words, if the bounds or bounds mode changes while there is an XrEventDataSpatialContainerBoundsChangedEXT event still queued, runtimes must report only a single event containing the last bounds change that occurred. Because apps can also poll a spatial container’s bounds directly with xrGetSpatialContainerBoundsEXT, the number of bounds changes from events can be different the number of changes from polling based on the timing of runtime generated bounds changes, app calls to xrPollEvent, and app calls to xrGetSpatialContainerBoundsEXT.

When a spatial container’s bounds changes, the spatial container’s local origin may change as well. For example, if a runtime allows a user to resize the spatial container’s bounds by dragging one of the container’s edges, the bounds and the local origin for that container will change when the user drags a single edge. In such situations, the runtime must change the bounds and the local origin simultaneously.

Runtimes must set infiniteBounds to XR_TRUE and set width, height, and depth to 0.0 to represent infinite bounds. Runtimes must set infiniteBounds to XR_FALSE and set width, height, and depth to finite positive numbers for finite bounds.

Runtimes must set bounds and infiniteBounds following the same rules as for XrSpatialContainerBoundsEXT.

Valid Usage (Implicit)

  • The XR_EXT_spatial_container extension must be enabled prior to using XrEventDataSpatialContainerBoundsChangedEXT

  • type must be XR_TYPE_EVENT_DATA_SPATIAL_CONTAINER_BOUNDS_CHANGED_EXT

  • next must be NULL or a valid pointer to the next structure in a structure chain
