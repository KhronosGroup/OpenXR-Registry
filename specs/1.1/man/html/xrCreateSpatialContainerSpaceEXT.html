xrCreateSpatialContainerSpaceEXT(3) Manual Page

Name

xrCreateSpatialContainerSpaceEXT - Create a space that is the origin of a spatial container

C Specification

The xrCreateSpatialContainerSpaceEXT function creates an XrSpace handle for the spatial container space of a specific spatial container.

// Provided by XR_EXT_spatial_container
XrResult xrCreateSpatialContainerSpaceEXT(
    XrSession                                   session,
    const XrSpatialContainerSpaceCreateInfoEXT* createInfo,
    XrSpace*                                    space);

Parameters

Parameter Descriptions

  • session is the XrSession that creates the space.

  • createInfo is a pointer to an XrSpatialContainerSpaceCreateInfoEXT containing parameters to create the space.

  • space is a pointer to a handle in which the created XrSpace is returned.

Description

The "spatial container space" for any given spatial container is a coordinate system with its origin at the center of that spatial container’s bounds. This space is typically used as the base space for functions like xrLocateSpace.

+X points to the right face of the container, +Y points to the top face of the container, and +Z points to the front face of the container. For example, if a container is gravity aligned, in front of the viewer, and the viewer is at the identity pose relative to the LOCAL space, runtimes must orient the container space with the identity orientation relative to the LOCAL space. Runtimes may set the pose of a container space relative to LOCAL space to any arbitrary pose when that container becomes visible.

Figure 1. Axes convention of spatial container space

The spatial container space is a non-world locked origin. Apps that want a world locked origin while in immersive mode can use a world locked space such as XR_REFERENCE_SPACE_TYPE_LOCAL.

Runtimes may change a spatial container space’s pose at any time, commonly to support a user moving a spatial container to a different position or rotation. Runtimes may also change the pose when transitioning between XR_SPATIAL_CONTAINER_BOUNDS_MODE_BOUNDED_EXT and XR_SPATIAL_CONTAINER_BOUNDS_MODE_IMMERSIVE_EXT bounds modes.

A spatial container space must continue to be a valid handle even if the spatial container it is for is destroyed with xrDestroySpatialContainerEXT. While a spatial container is not visible or destroyed, the spatial container space must be unlocatable relative to other spaces. XrSpaceLocation::locationFlags and XrViewState::viewStateFlags will be 0.

Valid Usage (Implicit)

  • The XR_EXT_spatial_container extension must be enabled prior to calling xrCreateSpatialContainerSpaceEXT

  • session must be a valid XrSession handle

  • createInfo must be a pointer to a valid XrSpatialContainerSpaceCreateInfoEXT structure

  • space must be a pointer to an XrSpace handle

Return Codes
On success, this command returns

  • XR_SUCCESS

  • XR_SESSION_LOSS_PENDING

On failure, this command returns

  • XR_ERROR_FUNCTION_UNSUPPORTED

  • XR_ERROR_HANDLE_INVALID

  • XR_ERROR_INSTANCE_LOST

  • XR_ERROR_LIMIT_REACHED

  • XR_ERROR_OUT_OF_MEMORY

  • XR_ERROR_RUNTIME_FAILURE

  • XR_ERROR_SESSION_LOST

  • XR_ERROR_SPATIAL_CONTAINER_CLOSED_EXT

  • XR_ERROR_VALIDATION_FAILURE
