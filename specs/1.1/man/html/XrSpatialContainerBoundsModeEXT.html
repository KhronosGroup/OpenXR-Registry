XrSpatialContainerBoundsModeEXT(3) Manual Page

Name

XrSpatialContainerBoundsModeEXT - Bounding mode of a spatial container

C Specification

The XrSpatialContainerBoundsModeEXT enumeration identifies different modes a spatial container’s bounds are able to be in.

// Provided by XR_EXT_spatial_container
typedef enum XrSpatialContainerBoundsModeEXT {
    XR_SPATIAL_CONTAINER_BOUNDS_MODE_BOUNDED_EXT = 1,
    XR_SPATIAL_CONTAINER_BOUNDS_MODE_IMMERSIVE_EXT = 2,
    XR_SPATIAL_CONTAINER_BOUNDS_MODE_MAX_ENUM_EXT = 0x7FFFFFFF
} XrSpatialContainerBoundsModeEXT;

Description

Spatial containers that are in bounds mode XR_SPATIAL_CONTAINER_BOUNDS_MODE_IMMERSIVE_EXT have additional requirements:

  • Runtimes must treat these spatial containers the same as a full-screen and immersive app created without spatial container usage, except for the behavior changes called out in https://registry.khronos.org/OpenXR/specs/1.1/html/xrspec.html#ext_spatial_container-changes_to_session_state.

  • Runtimes may provide additional extensions that enable immersive spatial containers to behave differently from full-screen and immersive apps created without this extension.

  • Runtimes must report infinite bounds for these spatial containers.

  • Runtimes may hide other spatial containers while an immersive spatial container is visible. Because this might be different per runtime, apps should not rely on spatial containers being automatically shown or hidden based on immersive spatial container visibility. Like all other visible state transitions, runtimes must queue an XrEventDataSpatialContainerVisibleChangedEXT event when a spatial container is hidden due to an immersive container being visible.

Note
Note

The above requirements imply that all runtimes can implement the OpenXR 1.x path without this extension by implicitly creating a spatial container, setting the container’s bounds mode to immersive, and requesting it be visible.
